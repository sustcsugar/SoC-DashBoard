# SoC 架构术语表

> **这份表的用法**
>
> 1. 讨论、读规范、读论文、写 ADR 中出现的任何新术语，**立即登记**，不要攒着。
> 2. 每条必须写「架构意义」。字典告诉你术语**是什么**；这里要记的是**架构师为什么关心它**。只写定义等于没写。
> 3. 标注首次出现阶段，便于按阶段复习。
> 4. **本表是唯一真相源。** 发现理解错误时改这里，不要去改零散的笔记。
> 5. 第 8 节「易混淆概念对照」是全文最有价值的部分。那里每一对混淆都会直接导致模型写错或决策做错。

## 1. 总线协议（Bus Protocol）

| 缩写 | 英文全称 | 中文 | 架构意义 | 阶段 |
|---|---|---|---|---|
| **AXI** | Advanced eXtensible Interface | 高级可扩展接口 | 五通道分离（AW/W/B/AR/R），地址与数据解耦。这是所有流水线、乱序完成、outstanding 优化的**物理前提**——非分离协议想做也做不到 | 0 |
| **AHB** | Advanced High-performance Bus | 高级高性能总线 | 非分离式，一次传输独占总线至完成。架构上意味着**带宽天花板由延迟直接决定**，无法靠 outstanding 掩盖延迟 | 0 |
| **APB** | Advanced Peripheral Bus | 高级外设总线 | 简单、低功耗、非流水。它的存在提醒你：低速外设需要单独的低带宽层，不要拖累主总线 | 0 |
| **ACE** | AXI Coherency Extensions | AXI 一致性扩展 | 带 cache 一致性的 AXI。多核/多集群共享数据时必需 | 2 |
| **CHI** | Coherent Hub Interface | 一致性集线器接口 | ARM 面向多核一致性的现代协议，替代 ACE。引入 Home Node、DMT/DCT/DWT、SLC 等概念 | 2 |
| **AW / W / B / AR / R** | Write Address / Write Data / Write Response / Read Address / Read Data | 写地址/写数据/写响应/读地址/读数据 | 五个独立通道，各自握手。★ **AW 与 W 分离是 AXI 特有死锁的经典来源**——两者可乱序到达，缓冲分配不当会互等 | 0 |
| **Outstanding** | Outstanding transactions | 未完成事务数 | ★ PSRAM 系统头号旋钮。有效带宽 ≈ 在途字节数 ÷ 延迟；outstanding 不足则总线空转 | 1 |
| **AxLEN** | Burst length | 突发长度 | 每事务拍数 − 1，AXI4 支持 1~256 拍。长 burst 提升总线效率但**恶化延迟抖动**——效率和实时性的直接冲突点 | 1 |
| **AxSIZE** | Transfer size | 传输大小 | 每拍字节数 = 2^AxSIZE。窄传输对寄存器访问合理，对内存带宽是纯浪费 | 1 |
| **AxBURST** | Burst type | 突发类型 | INCR（递增）/ WRAP（回绕）/ FIXED（固定）。缓存行填充用 WRAP，外设 FIFO 用 FIXED | 1 |
| **AxID** | Transaction ID | 事务标识 | 决定保序关系：**同 ID 必须保序，不同 ID 可乱序完成**。ID 数量是并发能力的硬约束，也是 HOL 阻塞的作用域 | 1 |
| **AxQOS** | QoS value | 服务质量位 | 4 位。★ **只是建议权重，不是任何保证**。必须配合入口调节器和从设备侧仲裁器才能形成契约 | 2 |
| **AxCACHE** | Cache attributes | 缓存属性 | 提示可缓存性/可缓冲性。影响写合并与预取行为，间接影响带宽效率 | 2 |
| **AxPROT** | Protection attributes | 保护属性 | 特权/安全/指令-数据。影响 MMU 与访问权限检查 | 2 |
| **AxLOCK** | Lock / exclusive access | 锁定/独占访问 | 原子操作支持。独占访问在多主设备下产生**重试流量**，是隐藏的带宽消耗 | 2 |
| **INCR burst** | Incrementing burst | 递增突发 | 最常用。地址逐拍递增，可跨 cache line | 1 |
| **WRAP burst** | Wrapping burst | 回绕突发 | 缓存行填充专用：从任意地址开始填满整行后回绕到行首 | 1 |
| **Narrow transfer** | — | 窄传输 | 传输大小 < 数据总线宽度。**有效带宽的直接损失**。外设访问常见，内存访问应避免 | 1 |
| **Write interleaving** | — | 写交织 | AXI3 允许多主设备写数据交错，AXI4 移除。★ 一个架构演进的教科书案例：**为了简化写通道的缓冲与仲裁，主动放弃了一个特性** | 2 |
| **Split transaction** | — | 分离式事务 | 请求与响应解耦。AXI 的核心特征，是 outstanding 得以存在的前提 | 0 |
| **Backpressure** | — | 反压 | 下游未就绪时通过 READY 拉低暂停上游。★ 反压会沿链路向上传播，这是**拥塞传导的机制**，不是局部现象 | 1 |
| **Credit-based flow control** | — | 基于信用的流控 | 发送前须持有信用额度，避免反压的回传延迟。NoC 与跨时钟域常用。信用耗尽 = 上游阻塞 | 2 |
| **QVN** | QoS Virtual Network | QoS 虚拟网络 | ★ 按契约类型隔离队列。贪婪主设备最多占用到「高水位线」，最后一位留给延迟敏感主设备 | 2 |
| **High tide mark** | — | 高水位线 | Arm 的机制：贪婪流量被限制到高水位线以内，为延迟敏感流量留出确定性余量 | 2 |
| **MPAM** | Memory System Resource Partitioning and Monitoring | 内存系统资源分区与监控 | Armv8.4 架构定义的 QoS/分区标准机制。这是「跨平台可移植的 QoS」的标准化答案 | 3 |
| **Regulator** | Ingress regulator | 入口调节器 | 在主设备侧限制流量（按带宽 / outstanding 数 / 事务间隔）。★ **过度调节本身会浪费带宽**——这是真实 trade-off，不是纯收益 | 2 |
| **Deadline** | — | 截止时间 | 实时主设备的硬约束（33.3ms@30fps、16.7ms@60fps）。错过产生**可见/可听伪影**，不是温和的性能下降 | 2 |
| **Isochronous** | — | 等时 | 有周期性截止时间要求的一类流量。需要最大延迟契约，不能只给平均带宽保证 | 2 |

## 2. 互联结构（Interconnect）

| 缩写 | 英文全称 | 中文 | 架构意义 | 阶段 |
|---|---|---|---|---|
| **Crossbar** | Crossbar switch | 交叉开关 | N×M 全连接。面积与布线随 N×M 增长。单层全交叉适合主设备数在十几路以内的场景 | 1 |
| **NoC** | Network-on-Chip | 片上网络 | 路由器 + 链路。适合主设备多、布线紧张。代价是引入路由/流控/虚通道的复杂度 | 2 |
| **Mesh / Ring / Torus / Tree** | — | 网状/环形/环面/树 | 各有带宽-延迟-面积取舍。Torus 需 dateline 才能避免环回死锁 | 2 |
| **Bisection bandwidth** | — | 对分带宽 | 把网络切成两半所需的最小链路带宽和。★ 衡量拓扑扩展性的标准指标。**共享总线的对分带宽是常数**——这是它无法克服的天花板 | 2 |
| **Arbitration** | — | 仲裁 | 在从设备侧决定谁获得共享资源。策略直接决定公平性与延迟分布 | 1 |
| **RR** | Round Robin | 轮询 | 每事务公平。★ **16-beat burst 对 1-beat single 时是错的**——burst 那路每字节只拿到 1/16 的机会 | 1 |
| **WRR** | Weighted Round Robin | 加权轮询 | 按权重分配。实现带宽型与延迟型分层的基本手段 | 1 |
| **DRR** | Deficit Round Robin | 差额轮询 | ★ **每字节公平**，O(1) 处理变长包。AXI burst 长度可变，所以这才是正确的公平语义 | 1 |
| **Fixed priority** | — | 固定优先级 | 最高优先级延迟最低，但低优先级会饿死。没有 aging 的固定优先级在实践中不可用 | 1 |
| **Aging** | — | 老化 | 等待越久优先级越高。**防饿死的标准手段**，与固定优先级配对使用 | 2 |
| **Lottery** | — | 彩票仲裁 | 按概率分配。概率上公平，实现简单，但延迟方差大——对实时流量不友好 | 2 |
| **Separable allocator** | — | 可分离分配器 | 请求-授权两阶段仲裁，大规模仲裁的硬件友好实现。先算请求矩阵，再对每个输出逐一路由授权 | 3 |
| **Stage** | — | 流水级 | 交叉开关内部流水线级数。增吞吐也增延迟，与目标频率联合权衡 | 2 |
| **VC** | Virtual Channel | 虚通道 | 共享物理链路上的多条逻辑队列。★ **避免队头阻塞的关键手段** | 2 |
| **Dateline** | — | 日期线 | 环面网络上的虚拟切割。环回会形成物理环，dateline 打破它以保持死锁自由 | 2 |
| **Escape VC** | Escape Virtual Channel | 逃逸虚通道 | Dally 的经典方法：用维序路由的逃逸通道保证**网络级**死锁自由 | 2 |
| **HOL blocking** | Head-of-Line blocking | 队头阻塞 | ★ 队头事务阻塞了后面无关事务。**同 ID 保序 + 单一队列 = HOL 必然发生**。这是「阻塞」的主要来源 | 1 |
| **Reorder buffer** | — | 重排缓冲 | 允许不同 ID 乱序完成，但向主设备按 ID 保序返回。**深度决定 HOL 阻塞的影响范围** | 1 |
| **Bridge** | — | 桥 | 协议/位宽/时钟域转换。★ 桥是最容易产生死锁的部件，因为它两侧的流控语义不匹配 | 2 |
| **SMMU / IOMMU** | System MMU | 系统内存管理单元 | 主设备侧的地址转换。TLB 缺失会给访问增加不可预测的延迟——对实时外设是隐性的抖动源 | 3 |

## 3. 存储子系统（Memory）

| 缩写 | 英文全称 | 中文 | 架构意义 | 阶段 |
|---|---|---|---|---|
| **DDR / LPDDR** | Double Data Rate (Low Power) | 双倍数据率（低功耗） | 深 bank 结构，行列缓冲优化空间大。带宽天花板高，但有效利用率受翻转/刷新严重制约 | 1 |
| **PSRAM** | Pseudo-Static RAM | 伪静态随机存储器 | 自带刷新逻辑的 DRAM，接口简化为 SRAM 式。**bank 并行度浅、延迟高**，这是它带宽天花板低的结构性原因 | 1 |
| **HyperBus / Xccela** | — | — | PSRAM 的两类串行接口。共享双向数据线，读写翻转开销大；有固定的命令/地址/空转周期开销 | 1 |
| **Channel / Rank / Bank Group / Bank / Row / Column** | — | 通道/秩/组/体/行/列 | 并行度的层次来源。★ **层级越深，可挖掘的并行度越高**。PSRAM 通常没有 bank group，这是与 DDR 的本质差距 | 1 |
| **Row buffer** | — | 行缓冲 | 当前打开的行。**行命中 = 低延迟高带宽；行失效 = 付 precharge + activate** | 1 |
| **Row hit / miss** | — | 行命中/失效 | ★ 行命中率是最重要的效率指标之一。真实案例的诊断起点就是行命中率，**不是带宽** | 1 |
| **Open-page / Closed-page** | — | 开页/闭页策略 | 访问后是否保持行打开。空间局部性好→开页；随机访问→闭页 | 1 |
| **tCL** | CAS Latency | 列地址选通延迟 | 读命令到数据输出的延迟 | 1 |
| **tRCD** | RAS-to-CAS Delay | 行激活到列选通延迟 | activate 到读写命令之间 | 1 |
| **tRP** | Row Precharge | 行预充电时间 | 关闭当前行所需时间 | 1 |
| **tRAS** | Row Active Time | 行激活保持时间 | 行必须保持打开的最短时间 | 1 |
| **tRC** | Row Cycle | 行周期 | 同 bank 两次 activate 的间隔 = tRAS + tRP。★ **tRC:tCK 从 SDRAM 的 9 恶化到 DDR3 的 28~39**——行冲突的代价逐代恶化，这是结构性趋势 | 1 |
| **tRRD** | Row-to-Row Delay | 不同 bank 间激活延迟 | 限制 bank 级并行的第一道约束 | 1 |
| **tFAW** | Four Activate Window | 四激活窗口 | 限制单位时间内的 activate 次数。★ **这是 bank 并行度的实际硬上限** | 1 |
| **tWTR** | Write-to-Read turnaround | 写到读切换延迟 | ★ **同 rank 内写→读的惩罚最大**，现代速率下可达 ~40 TCK，等于一次完整的行命中→行失效。跨 rank 几乎无惩罚 | 1 |
| **tRTW** | Read-to-Write turnaround | 读到写切换延迟 | 方向切换的另一半 | 1 |
| **tCCD** | Column-to-Column Delay | 列到列延迟 | 连续列命令的最小间隔 | 1 |
| **Read/write turnaround** | — | 读写方向切换 | ★ 最大的一类**可控**损耗。数据总线换向期间什么都传不了。批量化同向访问是核心优化手段 | 1 |
| **Refresh** | — | 刷新 | 定期重写电容。直接开销 ~1.7%@100MHz。★ **隐藏代价更大：刷新后所有 bank 关闭**，后续访问全部要付行失效延迟 | 1 |
| **tRFC / tREFI** | Refresh Cycle / Refresh Interval | 刷新周期/间隔 | 刷新占空比 ≈ tRFC/tREFI，是刷新直接开销的计算式 | 1 |
| **FR-FCFS** | First-Ready First-Come-First-Serve | 先就绪先服务 | DRAM 调度的经典算法：优先行命中，其次先到先服务。**用重排换取行命中率**——这是控制器里唯一能「无中生有」提升带宽的手段 | 1 |
| **Interleaving / hashing** | — | 交织/哈希 | 地址到 bank/channel 的映射方式。★ **决定热点是否被摊开**。错误的交织会让所有主设备打同一个 bank | 1 |
| **MSHR** | Miss Status Holding Register | 缺失状态保持寄存器 | ★ **CPU 侧 outstanding 的物理载体**。单个核常常无法跑满内存，就是因为 MSHR 数量封顶——这是「并发受限拐点」的经典成因 | 1 |
| **Line fill buffer** | — | 行填充缓冲 | 与 MSHR 同为并发上限的来源 | 1 |
| **Write combining buffer** | — | 写合并缓冲 | 把小写合并成大写，减少窄传输浪费。对写带宽效率至关重要 | 1 |
| **Hard macro / performance envelope** | — | 硬核 / 性能包络 | ★ **有硬核 IP 时唯一正确的建模层次：建模包络而非内部**。厂商手册给的就是这个（sustained BW、空载延迟、最大 outstanding、翻转开销） | 1 |
| **Sustained BW** | — | 持续带宽 | 扣掉各种开销后实际可达的带宽。★ 架构决策必须用它，**峰值只是引脚极限** | 1 |
| **Peak BW** | — | 峰值带宽 | 理论最大值。只能作为瀑布图的 100% 基准，不能作为设计目标 | 1 |

## 4. 性能指标（Metrics）

| 缩写 | 英文全称 | 中文 | 架构意义 | 阶段 |
|---|---|---|---|---|
| **Bandwidth** | — | 带宽 | 单位时间的数据量。★ 必须区分峰值 / 持续 / 有效三种，混用会导致错误决策 | 0 |
| **Effective bandwidth** | — | 有效带宽 | ★ **架构师真正关心的量**。它与峰值之间的差额就是要归因的损耗 | 1 |
| **Latency** | — | 延迟 | 请求到响应的时间。区分空载延迟与负载延迟 | 0 |
| **Tail latency** | — | 尾延迟 | p99/p999 延迟。★ **平均值骗人**——丢帧由尾延迟决定，不由平均值决定 | 2 |
| **Percentile** | p50 / p95 / p99 / p999 | 分位数 | 实时性分析的标准表达方式。汇报延迟必须给分布，不能只给均值 | 2 |
| **Jitter** | — | 抖动 | 延迟的波动/方差。实时外设的核心风险指标，比平均延迟重要 | 2 |
| **Throughput** | — | 吞吐 | 单位时间完成的事务数。与带宽不等价——事务大小不同则两者不成比例 | 0 |
| **Utilization (ρ)** | — | 利用率 | 到达率/服务率。ρ→1 时延迟爆炸。工程上通常设计在 ρ≈0.5（半功率点） | 1 |
| **Knee point** | — | 拐点 | 带宽-延迟曲线的转折点。★ 这是「能力边界」的标准表达形式 | 1 |
| **Concurrency-limited knee** | — | 并发受限拐点 | ★ **在途请求打满 outstanding/MSHR 导致的拐点。改配置能救**（加 outstanding、加 ID、加深缓冲） | 1 |
| **Device-limited knee** | — | 器件受限拐点 | ★ **总线/存储核心真饱和导致的拐点。只能重新流片**。与上者混淆会做出错误的立项决策 | 1 |
| **BDP** | Bandwidth-Delay Product | 带宽延迟积 | BW × latency。★ **定 outstanding 容量下限**：要跑满 4 GB/s、延迟 180ns，需在途 720 字节 | 1 |
| **Roofline** | — | 屋顶线模型 | 算术强度 vs 性能上界。★ 用作**前筛**：先分类「带宽受限/计算受限」，只对前者做完整 DSE | 3 |
| **Amdahl's Law** | — | 阿姆达尔定律 | 加速比受不可并行部分限制。用于衡量「优化某一部分」的理论上限 | 0 |
| **Little's Law** | — | 利特尔法则 | L = λW。★ **本工具的理论基石**。硬件建模应该用确定性样本路径版本 | 1 |
| **Rent's Rule** | — | 伦特定律 | I/O 数随逻辑面积亚线性幂律增长。★ Keller 的核心论据：**算力越大通信越稀缺**，低估它「often a fatal flaw」 | 0 |
| **USL** | Universal Scalability Law | 通用可扩展性定律 | 建模「加负载反而吞吐下降」的逆行扩展现象。适合多主设备争用场景 | 3 |
| **Jain's fairness index** | — | Jain 公平指数 | 公平性的单一数值表达。简单直观，但**只看分配量，不看被拖慢的程度** | 2 |
| **Stall-time fairness** | — | 停顿时间公平 | ★ Mutlu MICRO'07。衡量**被干扰拖慢了多少**，比带宽公平更贴近真实体验 | 2 |
| **ADRS** | Average Distance from Reference Set | 距参考集的平均距离 | ★ 衡量近似 Pareto 前沿质量的标准指标。做 DSE 就该报这个 | 3 |
| **Pareto frontier** | — | 帕累托前沿 | 不被任何其他解支配的解集。多目标（带宽/面积/功耗）决策的标准表达 | 3 |

## 5. 建模方法与形式化（Modeling & Formal Methods）

| 缩写 | 英文全称 | 中文 | 架构意义 | 阶段 |
|---|---|---|---|---|
| **DES** | Discrete Event Simulation | 离散事件仿真 | ★ **本项目的机制**。事件驱动的 Verilog 仿真器就是一个 DES 引擎——事件=信号跳变。时间只在事件发生时跳跃 | 0 |
| **Time-stepped** | — | 逐拍推进 | 固定步长推进。对比 DES：**空闲期照样要走完，是纯浪费** | 0 |
| **TLM** | Transaction-Level Modeling | 事务级建模 | 用事务而非信号描述系统，比 RTL 快几个数量级 | 0 |
| **UT** | Untimed | 无时序 | 只做功能，不含时间信息（TLM-1.0） | 0 |
| **LT** | Loosely-Timed | 松耦合时序 | 每事务两个时序点（请求/响应）。便宜，但**抓不到争用** | 0 |
| **AT** | Approximately-Timed | 近似时序 | 每事务四个时序点（BEGIN_REQ/END_REQ/BEGIN_RESP/END_RESP）+ 多相位。★ **存储子系统与互联的吞吐/延迟分析必须用 AT**，LT 不够 | 0 |
| **CA** | Cycle-Accurate | 周期精确 | 每个时钟可观测状态。慢几个数量级 | 0 |
| **Executable specification** | — | 可执行规格 | ★ 架构探索阶段的正式产出物，后续实现以它为准。传统上却常用「静态表格 + 临时脚本」，这是问题所在 | 0 |
| **DSE** | Design Space Exploration | 设计空间探索 | ★ 系统扫掠而非猜测。这是架构师的核心工作方法，也是本项目的产出目标 | 3 |
| **DoE** | Design of Experiments | 实验设计 | 统计学的实验方法论。Plackett-Burman 筛选源自此处 | 3 |
| **Plackett-Burman** | — | 普拉克特-伯曼设计 | ★ DSE 第一步的稀疏因子筛选：用少量实验找出**哪些旋钮真的重要** | 3 |
| **Surrogate model / RSM** | Response Surface Method | 代理模型/响应面法 | 用少量仿真点拟合近似模型，降低后续评估成本 | 3 |
| **Sobol indices** | — | Sobol 指数 | ★ 方差分解敏感度，**交互感知**。单旋钮 Tornado 图会漏掉交互导致的排序反转 | 3 |
| **Tornado chart** | — | 龙卷风图 | 单旋钮敏感度的标准沟通图。★ 但**不能单独作为结论** | 3 |
| **Analytical model** | — | 解析模型 | 闭式解模型，微秒级出结果。适合海量扫掠，**抓不到涌现行为** | 0 |
| **Queueing theory** | — | 排队论 | 延迟建模的数学基础 | 1 |
| **M/M/1** | — | 泊松到达/指数服务/单服务器 | 最简单的队列模型。Wq = ρ/(μ−λ) | 1 |
| **M/D/1** | — | 泊松到达/确定性服务 | 比 M/M/1 更贴近固定长度 burst 的硬件场景 | 1 |
| **M/G/1** | — | 泊松到达/一般服务时间 | 服务时间的变异性有影响时使用 | 1 |
| **Jackson network** | — | 杰克逊网络 | 开环排队网络的乘积解。★ 前提是**泊松到达 + 平稳性**。帧同步流量是周期性非平稳的，**套用会出错** | 3 |
| **MVA** | Mean Value Analysis | 均值分析 | 闭环排队网络的解法 | 3 |
| **Operational laws** | — | 运算定律 | ★ 基于**可观测量**的定律，不依赖概率假设。Little's Law 的确定性版本属于此 | 1 |
| **Network calculus** | — | 网络演算 | 到达曲线 + 服务曲线。**拒绝概率，给安全上界**。通常悲观 3~10 倍 | 3 |
| **Real-time calculus** | — | 实时演算 | 网络演算的实时扩展，把计算与通信放进同一个 min-plus/max-plus 框架 | 3 |
| **TFA** | Total Flow Analysis | 总流分析 | 网络演算中最保守（但最安全）的聚合方式 | 3 |
| **SFA** | Separated Flow Analysis | 分离流分析 | 比 TFA 更紧、扩展性更好，是实际常用选择 | 3 |
| **Flow equivalence** | — | 流等价 | ★ 层次化建模的形式化依据：先粗后细，把子系统当单个服务中心。「现在把总线当一个服务中心，以后再展开」说得通的理由 | 1 |
| **Deterministic Little's Law** | — | 确定性利特尔法则 | ★ 样本路径版本：**任意有限窗口成立，不需要平稳性假设**。硬件建模应该用这个，而不是随机版本 | 1 |
| **Model calibration** | — | 模型校准 | 把模型对齐到实测/硅后数据。Arm 的 JD 明确要求「model-to-silicon correlation」 | 3 |

## 6. 失效模式与可靠性（Failure Modes）

| 缩写 | 英文全称 | 中文 | 架构意义 | 阶段 |
|---|---|---|---|---|
| **Deadlock** | — | 死锁 | 互相等待形成环，系统永久停滞。★ **最严重的失效**。必须显式建模有限缓冲资源，否则模型里根本无法产生环 | 2 |
| **Livelock** | — | 活锁 | 一直在动但没有进展。比死锁隐蔽——看起来系统很忙 | 2 |
| **Starvation** | — | 饿死 | 某主设备长期仲裁零获胜。固定优先级的必然结果，必须用 aging 防治 | 2 |
| **Priority inversion** | — | 优先级反转 | 高优先级事务被低优先级**持有的资源**阻塞。资源所有权与优先级不匹配导致 | 2 |
| **Interlock** | — | 互锁 | 总线间互相等待形成的依赖。中文语境常指依赖环 | 2 |
| **Congestion** | — | 拥塞 | 系统级的队列积累与传播。★ 需要改拓扑或配额，**不是加局部缓冲能解决的** | 2 |
| **Blocking** | — | 阻塞 | 单个事务因资源不可用被推迟。★ 可局部修（改缓冲深度） | 1 |
| **No-forward-progress** | — | 无进展 | 系统整体停滞。运行时检测的目标状态 | 2 |
| **CDG** | Channel Dependency Graph | 通道依赖图 | Dally 的经典死锁分析工具，把死锁问题转化为图论问题 | 2 |
| **ECDG** | Extended Channel Dependency Graph | 扩展通道依赖图 | ★ **三层依赖建模：协议层 / 互联层 / 实现层**（共享 FIFO、共享 credit 计数器）。检测归结为找环。证据：静态分析 1.28 秒 vs 形式化方法 56 分钟 | 2 |
| **Wait-for graph** | — | 等待图 | 事务 → 阻塞它的资源 → 持有该资源的事务。**环 = 死锁** | 2 |
| **Double-path deadlock** | — | 双路径死锁 | ★ **AXI 特有**：AW 与 W 通道分离，两者可乱序到达，缓冲分配不当会互等 | 2 |
| **Loop-path deadlock** | — | 环路死锁 | 经典的循环依赖 | 2 |
| **Bridge deadlock** | — | 桥死锁 | ★ 协议转换处（如 AXI↔AHB）的经典问题：两侧流控语义不匹配 | 2 |
| **AXI write-stall gap** | — | AXI 写停滞缺口 | ★★ **AMBA 规范的一个洞**：W 通道**没有协议级约束**限制写主设备持有授权后多久才提供数据。**真实的 AXI 死锁经常源于这里，不是路由环**。必须作为一等定时行为建模 | 2 |
| **Timeout / escalation** | — | 超时 / 优先级升级 | 超时后强制提升优先级插入。实时保护的兜底机制 | 2 |
| **Isolation** | — | 隔离 | 资源分区，保证实时流不受贪婪流影响。ATAM 意义上的「权衡点」——隔离换效率 | 3 |
| **RAS** | Reliability, Availability, Serviceability | 可靠性/可用性/可维护性 | 与性能并列的架构目标。ECC、奇偶校验、错误注入都是带宽的隐性成本 | 3 |

## 8. 易混淆概念对照 ★ 全文最有价值的部分

这一节每一对混淆都会**直接导致模型写错或决策做错**。

| 容易混淆的一对 | 区别 | 为什么这个区别重要 |
|---|---|---|
| **阻塞 Blocking** vs **拥塞 Congestion** | 阻塞是**单个事务**因资源不可用被推迟；拥塞是**系统级**的队列积累与传播 | 阻塞可以局部修（加深缓冲、拆 ID）；拥塞必须改拓扑或配额。用错药方会白花面积 |
| **并发受限拐点** vs **器件受限拐点** | 前者是在途请求打满 outstanding/MSHR；后者是总线或存储核心真饱和 | ★★ **前者改配置能救，后者只能重新流片**。研究原话：「报告『你在拐点上』却不区分这两者的工具是误导性的」。**混淆会导致错误的立项决策** |
| **翻转受限** vs **器件受限** | 两者**总线占用率都是 100%**，但前者是时间花在读写换向上，后者是花在传数据 | ★★ **这是被遗漏的第三种失效模式。** 实测：PSRAM 稳态下总线占用 100%，其中 20%~49% 是翻转，真正传数据只有 52%~80%。用"总线占用率"根本区分不出来，必须看**数据占线时间占比**。前者调调度参数就能救，后者要重新流片 |
| **每字节公平的代价** | DRR 做到每字节公平，RR 做不到 | ★ 实测：同一场景下 DRR 总带宽 1.796 GB/s，RR 3.202 GB/s——**公平性让总吞吐掉了 44%**。原因是给窄 burst 主设备一半带宽，等于让总线上充斥小事务，每事务的固定开销把效率吃光。**公平不是免费的** |
| **逆行扩展（retrograde scaling）** | 加的负载超过拐点后，达成带宽**反而下降** | ★ 实测：PSRAM 供载从 3.2 加到 7.2 GB/s，达成带宽从 2.486 **降到** 2.265 GB/s。因为负载越高读写越混杂、翻转越频繁。**实践含义：给已饱和的存储加压不会提吞吐，只会抬延迟、降效率** |
| **每事务公平** vs **每字节公平** | RR 给的是每事务公平；DRR 给的是每字节公平 | 16-beat burst 和 1-beat single 混跑时，RR 让 burst 那路**每字节只拿到 1/16 的仲裁机会**。这是很多自研模型里隐藏的正确性 bug |
| **带宽公平** vs **停顿时间公平** | 前者看拿到了多少带宽；后者看**被干扰拖慢了多少**（Mutlu MICRO'07） | 拿到同样带宽的两路主设备，实际被拖慢的程度可能差很多。实时性分析必须用后者 |
| **仲裁 Arbitration** vs **调节 Regulation** | 仲裁在**从设备侧**选谁；调节在**主设备侧**限谁 | ★ 它们是互补的两层，缺一不可。而且**过度调节本身会浪费带宽**——这是真实 trade-off，不是纯收益 |
| **延迟 Latency** vs **吞吐 Throughput** | 延迟是一次访问的时间；吞吐是单位时间完成量 | 深流水能提吞吐但增延迟。**实时外设要的是延迟上界，不是高吞吐** |
| **峰值带宽** vs **持续带宽** vs **有效带宽** | 峰值=引脚极限；持续=扣掉固有开销后可达；有效=实际跑出来的 | ★ 拿峰值做设计目标是最常见的新手错误。架构决策必须用持续带宽，评估用有效带宽 |
| **Outstanding 数** vs **队列深度** | outstanding 是**已发出等待响应**的事务数；队列深度是**等待发出**的排队容量 | 两者是不同的资源。增加队列深度但不加 outstanding，只会让等待更长而不是带宽更高 |
| **事务 Transaction** vs **拍 Beat** | 一个 burst 事务包含多拍数据 | 统计带宽必须换算到字节，否则「事务数」会被 burst 长度差异误导。这也是 RR 出错的根源 |
| **死锁 Deadlock** vs **活锁 Livelock** vs **饿死 Starvation** | 死锁=永久停；活锁=一直在动无进展；饿死=某一路零进展而系统整体正常 | 三种失效的诊断方法和修复手段完全不同。监控指标也不一样 |
| **一致性 Coherency** vs **连续性 Consistency** | Coherency 是缓存数据的一致性；Consistency 是内存访问顺序的可见性模型 | 中文都常译作「一致性」，但一个是缓存协议问题，一个是内存模型问题。混用会导致沟通失效 |
| **QoS 建议** vs **QoS 保证** | AxQOS 位是**建议权重**，不影响也不会保证任何东西 | ★ 只有配合入口调节器 + 从设备侧仲裁才能形成契约。**把 QoS 位当成保证是危险的误解** |
| **平均延迟** vs **尾延迟** | 平均延迟是均值；尾延迟是 p99/p999 | ★ **平均值骗人**。丢帧、音频欠载、可见伪影全部由尾延迟决定 |
| **MSHR 数** vs **outstanding 数** | MSHR 是 CPU 侧的实现载体；outstanding 是链路级的协议能力 | 单个核常常无法跑满内存，就是因为 MSHR 封顶——这是「并发受限拐点」最经典的成因 |
| **行命中率** vs **带宽利用率** | 行命中率是 DRAM 内部效率；带宽利用率是外部表现 | ★ 真实案例的诊断顺序是**先看行命中率，再看带宽**。反过来会误判 |
| **静态分析** vs **仿真** 用于死锁检测 | 静态分析在依赖图上找环；仿真靠随机激励碰运气 | ★ 证据很硬：静态分析 1.28 秒，形式化方法 56 分钟，UVM 随机验证要数月。**死锁检测应该用静态分析** |

## 9. 关键公式速查

| 公式 | 表达式 | 用途与注意 |
|---|---|---|
| **Little's Law（确定性）** | `L = λW` | ★ 本工具的理论基石。**样本路径版本在任意有限窗口成立，无需平稳性假设**——硬件建模必须用这个版本 |
| **有效带宽（Little's Law 的内存形式）** | `BW_eff = 在途字节数 ÷ 延迟` | ★ PSRAM 系统的核心关系。延迟高则需要的在途字节数暴增。**注意这是必要条件不是充分条件**——可达到的并发被 outstanding 上限封顶 |
| **带宽延迟积 BDP** | `BDP = BW_target × latency` | 定 outstanding 容量的下限。例：目标 4 GB/s、延迟 180ns → 需在途 720 字节 |
| **利用率** | `ρ = λ / μ` | ρ→1 时延迟爆炸。工程上常设计在 ρ≈0.5（半功率点）。**这是策略选择，不是自然定律** |
| **M/M/1 排队延迟** | `Wq = ρ/(μ−λ)`，`Lq = ρ²/(1−ρ)` | 单服务器粗估。服务时间变异性影响在 M/G/1 里 |
| **M/D/1 排队延迟** | `Wq = ρ/(2μ(1−ρ))` | 固定服务时间。比 M/M/1 更贴近定长 burst |
| **Amdahl 定律** | `S = 1 / ((1−p) + p/s)` | 优化某一部分的理论上限。**用于判断「优化这个旋钮值不值得」** |
| **Rent's Rule** | `N_io = k × N_gate^p`，p ≈ 0.5~0.7 | ★ 通信需求随逻辑规模亚线性增长 → **算力越大通信越稀缺**。这是「数据移动是新前沿」的定量依据 |
| **有效带宽分解** | `BW_eff = BW_peak × η_proto × η_turnaround × η_refresh × η_row × η_arb` | ★ 瀑布图的数学形式。每一项都对应一个可测量的计数器 |
| **总线时间恒等式** | `数据占线 + 翻转 + 空闲 = 1` | ★ 本工具瀑布分解**不重复计数**的依据。有效带宽 = 数据传输期速率 × 数据占线占比。系统侧损耗按**数据传输期速率**折算，不是按峰值——按峰值算会和「器件固有开销」项重复计入同一段时间（实测会超出峰值 17%） |
| **翻转摊销** | `翻转占线占比 ≈ turnaround / (每事务数据时长 × 批长度 + turnaround)` | ★ 批长度是这个式子里唯一的可调项。实测：批长度 2 时翻转占 40%，批长度 5.4 时降到 19% |
| **刷新开销** | `η_refresh = 1 − tRFC / tREFI` | 直接开销约 1.7%@100MHz。**隐藏代价（刷新后所有 bank 关闭）需另算** |
| **行冲突代价** | `≈ tRC / tCK` | 从 SDRAM 的 9 恶化到 DDR3 的 28~39。**逐代恶化，应作为趋势编码进模型而非常数** |
| **事务字节数** | `bytes = (AxLEN + 1) × 2^AxSIZE` | 统计带宽必须换算到字节 |
| **总线理论峰值** | `BW_peak = width_bytes × freq × 2`（DDR） | 瀑布图的 100% 基准 |
| **减速比（停顿时间公平）** | `slowdown_i = 单独运行延迟 / 共享运行延迟` | Mutlu 的指标。比「拿到多少带宽」更贴近真实体验 |

## 附：本项目已定的建模约定

以下约定不是通用定义，是**本工具的实现选择**，登记在此以便查证：

| 约定 | 选择 | 理由 |
|---|---|---|
| 时间分辨率 | 1 ns | 够表达 AXI 握手与 PSRAM 延迟量级，整数运算无浮点误差 |
| 同刻事件排序 | 确定性优先级 | 保证可复现，扫掠时结果可比 |
| 随机源 | 按组件独立 seed | 单个组件的参数变化不扰动其他组件的随机序列，便于差分对比 |
| 缓冲 | 全部有界且可配 | **死锁可检的前提**——无界缓冲在数学上不可能形成依赖环 |
| 仲裁默认 | DRR + aging | 避免每事务公平的错误语义，同时防饿死 |
| QoS 默认 | CPU=13（非 15） | 留出升级空间给濒临饿死的实时主设备 |
| 带宽统计 | 按字节，按主/从/方向/时间桶 | 事务数会被 burst 长度差异误导 |
| 自校验 | 上界 + Little's Law + 守恒 | 架构工具必须自证，否则结论不可信 |

## 附二：工程经验（踩过的坑）

这一节记的是**实现层面的**教训，不是领域知识。留在这里是因为它们都花了不少时间才定位。

| 现象 | 根因 | 教训 |
|---|---|---|
| 方向翻转占了 64% 的时间窗，但写缓冲明明配了 4KB | 控制器**每收到一个事务就立即发出**，队列从不积累，批处理无货可批 | **读写不对称是物理事实**：读要按需服务，写要攒批。把读写对称处理，批处理永远不会发生 |
| 加了 `min_batch_bursts` 仍然每次换向 | "读饥饿超时"量的是**最老请求等了多久**——饱和系统里那个数永远很大，条件恒为真 | 饥饿计时的正确语义是"**当前方向已经压制对向多久**"，不是"请求等了多久" |
| 翻转损耗恒为 0，模型完全忽略它 | `_pick` 在做决策时就改了"当前方向"，`_issue` 检查时永远看不到变化 | 调度**决策**与总线**实际行为**是两个状态，不能共用一个变量 |
| Little's Law 误差 5.4%，且**误差与 outstanding 压力成正比** | 延迟从"想发起"算起，并发数从"握手完成"算起——两者基准不同 | ★ 误差与某个压力指标**成正比**是最有价值的线索：那不是噪声，是系统性口径错误。Little's Law 两侧必须同源 |
| DRR 出现 3%/97% 的字节份额，与 RR 一样 | 每轮只给每个流**一个**授权，而不是"每流每轮获得 quantum 字节配额" | DRR 的语义是**字节配额**，不是事务配额。小包流应该在配额内多发几个包 |
| 所有格式的 `savefig` 都让进程静默消失，exit 127，无 traceback | conda-forge 把 matplotlib 解到 3.11.2 并拉入 PySide6（395 个 Qt6 DLL），与手装的 pip matplotlib 混在一起，触发原生崩溃 0xc06d007f | ★ 崩在**原生层**时 Python 异常处理完全失效。排查路径：最小复现脚本二分定位到具体 API → 对比可用环境的包版本 → 锁版本。见 `environment.yml` 的版本锁定说明 |
| 守恒校验在预热场景下永远差一个固定量 | 预热清零了统计计数器，但当时**已发出未完成**的事务不在清零范围内 | 预热不是"清零"而是"**重置观测原点**"：Gauge 记录原点、守恒记录基准在途量，两者都要移，不能只清计数 |
